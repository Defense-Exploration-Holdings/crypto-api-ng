# License notes

**Status: decided 2026-11-14. The whole package, original and new code, is MIT.** This file records the reasoning and what to keep in mind.

- This project is a port of [`nf404/crypto-api`](https://github.com/nf404/crypto-api), vendored here as the `crypto-api/` git submodule (see `.gitmodules`). A port of its algorithms and API surface is a derivative work, so the original copyright and license notice must be preserved in this repository and in published packages.
- The original is reported to be MIT-licensed (`crypto-api/LICENSE.md`, "Copyright (c) 2015 nf404"; `license: "MIT"` and author Aleksandr Mogilnikov in its `package.json`). Verified against the submodule. The package ships `packages/crypto-api/LICENSE`: the original MIT text with a second copyright line for the new code, and the package's `license` field is `MIT`. The same file is the repository's top-level `LICENSE`.
- The new Zig/wasm code is MIT too (chosen by the maintainer as "Apache or MIT, whichever is better for us"; MIT because the vendored original is MIT, so existing users get one license for the whole drop-in, with no second set of terms and no patent-clause surprise). The copyright line is `Copyright (c) 2026 Defense Exploration Holdings`; confirm the exact legal name of the entity before the first release. `package.json` stays `"private": true` until the release gates and the npm name are settled, so nothing can be published by accident.
- Zig's standard library (compiled into the wasm) is MIT-licensed; no notice is required for the binary beyond the above, but keep this in mind if third-party Zig packages are added later. Record any added dependency here.
- Test vectors taken from standards (NIST, RFCs) are fine to reuse; test vectors copied from the original's test suite fall under the original's license.
